# キャリアマップ 設計書（v0.1）

最終更新: 2026-09-30

## 1. 目的と原則

個人の属性・地域・スキルを入力すると、「自分と似た条件の人が社会の中でどの位置にいるか」「どの条件を変えると選択肢が広がる可能性があるか」を、公開統計から可視化する。

設計上の原則:

1. **断定しない** — 表示する数値はすべて「集団の統計」であり、個人の予測ではない。
2. **出典と不確実性を必ず示す** — すべての数値に、出典・調査年・サンプル数（または推計母数）・推定方法を付ける。
3. **推定と実測を区別する** — マイクロデータから直接集計した値、集計表からモデルで補完した値、学術研究の推定値を UI 上で区別する。
4. **相関と因果を区別する** — what-if シミュレーションで因果的な解釈ができるのは、研究で因果推定された効果（教育の収益率など）だけ。それ以外は「条件の違う集団の比較」と表示する。
5. **入力はサーバーに送らない** — 計算はすべてブラウザ内で行う。入力値は端末にだけ保存する（オプトイン）。
6. **無料・静的** — 無料の公開データのみを使い、静的サイト（GitHub Pages / Vercel）として配信する。

## 2. 制約

| 項目 | 内容 |
|---|---|
| 体制 | 個人開発 |
| 予算 | 無料データ・無料ホスティングのみ |
| ユーザー | 多言語・多国籍（UI は日本語と英語から始め、辞書ファイルで拡張する） |
| 配信 | 静的ホスティング（GitHub Pages を第一候補、Vercel でも動く構成） |
| API キー | 取得を前提にしない。キーが要る API（e-Stat API、Census API、BEA API）は、キーなしのファイルダウンロードで代替する |

## 3. アーキテクチャ

```
┌───────────────── ビルド時（ローカル / GitHub Actions） ─────────────────┐
│  pipeline/ (Python, uv)                                             │
│   fetch  → data/raw/      公開ファイルをダウンロード（.gitignore 対象）       │
│   build  → web/public/data/*.json  小さく集計済みの配信用データ               │
└─────────────────────────────────────────────────────────────────────┘
                          │ 静的ファイル
                          ▼
┌───────────────── 実行時（ブラウザのみ） ─────────────────┐
│  web/ (Vite + React + TypeScript)                     │
│   入力フォーム → 推定エンジン(TS) → 可視化                   │
│   i18n (ja / en)、入力は localStorage（任意）              │
└──────────────────────────────────────────────────────┘
```

- **サーバーを持たない。** 集計・推定済みの JSON を配信し、個人の位置の計算（パーセンタイルなど）はブラウザ内で行う。
- **生データはリポジトリに入れない。** `data/raw/` は `.gitignore` の対象にし、`pipeline` が再現可能な手順で取得する。
- **配信データのサイズ目標**は国ごとに 1〜3 MB（gzip 後）。大きくなったら国・指標ごとに分割して遅延読み込みする。

### 技術選定

| 層 | 選定 | 理由 |
|---|---|---|
| データ処理 | Python 3.12 + uv + Polars | 数百万行の個票を高速に集計できる |

| i18n | 自前の辞書（`ja.ts`, `en.ts`） | 依存を増やさない |
| テスト | Vitest（推定エンジン）、pytest（パイプライン） | |

## 5. データモデル

### 5.1 共通スキーマ（配信用 JSON）

国ごとに `web/public/data/{country}/` に `meta.json`（次元のラベル・出典・定義）、`national.json`（全国のセル）、`region-{code}.json`（地域のセル。必要になったときに読み込む）を置く。

実際のセルは容量を抑えるため `{"occ|age|sex|edu": [n, 平均, p10, p25, p50, p75, p90, method]}` の配列で持つ。`*` は「計」、職業の `M..` は大分類を表す。以下は概念上のスキーマ。

```jsonc
{
  "country": "JP",
  "currency": "JPY",
  "source": [{ "id": "wcs2025", "name": {...}, "url": "...", "year": 2025 }],
  "dims": {
    "occupation": [{ "code": "...", "label": { "ja": "...", "en": "..." }, "isco": "25" }],
    "region":     [{ "code": "13", "label": {...} }],
    "age":        [{ "code": "30-34", "min": 30, "max": 34 }],
    "sex":        ["M", "F", "T"],
    "education":  [...]
  },
  // セル = 次元の組み合わせ。欠けた次元は「計」
  "cells": [
    {
      "key": { "occupation": "...", "age": "30-34", "sex": "T" },
      "n": 12345,               // サンプル数（日本は推計労働者数）
      "mean": 5120000,          // 年収の平均（通貨単位）
      "q": [p10, p25, p50, p75, p90],  // 分位点
      "method": "direct | lognormal-fit",
      "source": "wcs2025"
    }
  ]
}
```

### 5.2 年収の定義

国ごとに年収の定義が違うため、国をまたいで比較するときは注記を必ず表示する。

- **日本**: `きまって支給する現金給与額 × 12 + 年間賞与その他特別給与額`。残業代を含める（米国の WAGP と揃えるため）。一般労働者のみ（短時間労働者は除く）。民営・常用労働者10人以上の事業所。
- **米国**: `WAGP`（過去 12 か月の賃金・給与）× `ADJINC`。フルタイム・通年勤務者（週 35 時間以上 × 年 50 週以上）に限定する。

## 6. 推定方法

### 6.1 米国（個票から直接集計）

1. フルタイム・通年勤務の就業者に絞る。
2. 年齢階級・性別・学歴・職業（SOC の大分類と詳細）・州の組み合わせごとに、個人ウェイト `PWGTP` 付きの分位点を計算する。
3. サンプル数が閾値（n < 30）未満のセルは出力しない。
4. **フォールバック**: ブラウザ側で、指定条件のセルがなければ優先度の低い次元から順に「計」に置き換えて探す（例: 州 → 学歴 → 性別）。どの条件を外したかを UI に明示する。

### 6.2 日本（集計表からの分布推定）

日本は個票が使えないため、e-Stat の Excel 集計表（API キー不要）を組み合わせて分布を推定する。セルごとに推定方法を記録し、UI に表示する。

| セル | 平均・労働者数 | 分布の形 | method |
|---|---|---|---|
| 性×年齢×学歴（と全体） | 学歴 第1表 | 学歴 第3表の所定内給与額の度数分布（性×学歴×年齢） | 1 histogram |
| 職種（小分類 145・大分類 11）×性×年齢 | 職種 第1・5・6・7表 | 対数正規分布。幅 σ は職種の分布特性値（第17〜19表）から推定し、年齢で補正 | 2 lognormal |
| 都道府県×性×年齢 | 都道府県別第1表（産業計） | 全国の同じ性×年齢の分布を、都道府県の平均に合わせて拡大縮小 | 1 histogram |
| 都道府県×職種大分類×性 | 都道府県別第2表 | 対数正規分布（大分類の σ） | 2 lognormal |

- **度数分布から**: 学歴の区分（中学＋高校など）をまとめるときは度数を足し合わせ、階級内を線形補間して分位点を出す。算出した分位点は公表値とほぼ一致する（全体の中央値 296.8 千円に対し公表値 296.6 千円）。
- **月額から年収へ**: 度数分布は所定内給与額（月額）なので、`年収の平均 ÷ (12 × 所定内給与額の平均)` を掛けて年収に換算する。賞与と残業代が給与に比例するという仮定を置いている。
- **対数正規**: `σ = ln(p90 / p10) / (2 × 1.2816)`。職種の分布特性値には年齢の内訳がないので、`σ(性, 年齢) / σ(性, 全年齢)` を掛けて年齢で補正する。平均が一致するよう `μ = ln(平均) − σ² / 2`。
- **公表の閾値**: 推計労働者数 1,000 人未満のセルは出さない。

**既知の限界**

- 職種×学歴、職種×都道府県（小分類）の表は公表されていない。
- 職種の分布の幅を月額の所定内給与から推定しているため、賞与のばらつきは反映されていない。
- 表示する人数は標本数ではなく推計労働者数である。

### 6.3 パーセンタイルの計算（ブラウザ）

- (対数年収, 正規分布の z 値) の 5 点を単調 3 次補間（Fritsch–Carlson）で結び、両端は線形に外挿する。分位点を正確に通り、対数正規分布なら厳密に一致する。米国の個票は年収が「10万ドル」のような切りの良い額に集中するので、線形補間では密度がギザギザになる。3 次補間にしたのはそのため。
- **分布曲線の描画**は、5 つの分位点に最小二乗で当てはめた対数正規分布を使う。5 点しかない情報から細かい凹凸を描くと、実際以上の精度があるように見えてしまうため。

### 6.4 手取り・生活費（Phase 2）

表示する金額を「額面」「手取り」「手取り（物価調整後）」から選べる。変換は年収について単調なので、分位点にそのまま適用する（手取りの中央値 ＝ 中央値の人の手取り）。平均は変換後の近似値になる。

**手取りの概算**（単身・扶養なし・給与収入のみ。`web/src/engine/tax.ts`）

| | 日本（令和7年分） | 米国（2025年） |
|---|---|---|
| 社会保険 | 健康保険 5.0%（協会けんぽ全国平均の折半）、介護保険 0.795%（40〜64歳）、厚生年金 9.15%、雇用保険 0.55%。上限は標準報酬月額から近似 | Social Security 6.2%（上限 $176,100）、Medicare 1.45%、$200,000 超は +0.9% |
| 所得税 | 給与所得控除・基礎控除（令和7・8年の特例加算を含む）、復興特別所得税 2.1% | 標準控除 $15,750、連邦税率表 |
| 地方税 | 住民税 10%（基礎控除 43万円、調整控除）＋均等割 5,000円 | 州所得税（`pipeline/career_pipeline/labels/us_state_tax_2025.json`）。市税は含まない |

州税は税率表・標準控除・人的控除・税額控除に加え、単純な線形の段階的縮小（UT・WI・CT・CA）を計算する。NY・CT の高所得者向けの取り戻し（recapture）、AR の控除の縮小などは、JSON の notes に記載しているだけで計算していない。

含まないもの: 扶養・配偶者・iDeCo 等の控除、401(k)、州の給与税（CA SDI など）、地方の所得税（NYC など）、健康保険料の実額（米国）。

**物価調整**: 手取り ÷ (地域の物価水準 / 100)。日本は消費者物価地域差指数（2025年、都道府県、総合）、米国は BEA Regional Price Parities（2024年、州、All items）。地域を指定しない場合は 100。国をまたぐ比較では、国内の地域差で割ったうえで購買力平価で換算する。

### 6.5 地図

- 都道府県・州を同じ大きさの正方形で並べるタイルグリッド地図にした。実際の地図では東京・大阪・神奈川が小さすぎて読めないため。境界データのダウンロードやライセンス表記も不要になる。
- 色は単色（青）の 7 段階。値の範囲を等間隔に区切る。データがない地域は灰色。
- 全地域で同じ種類の集団を比べるため、キー（職業・年齢・性別・学歴の組み合わせ）を 1 つに固定する。半数以上の地域が公表している最も詳しいキーを選ぶ。
- 地図用に、全地域のセルを 1 ファイルにまとめた `regions.json` を作る。米国は容量を抑えるため、職業は大分類まで、条件は 2 つまでに絞る（約 230KB、gzip 後）。

### 6.6 国の追加（Phase 3）

- **国の登録**: `web/src/engine/countries.ts` に国コード・通貨・入力単位・比較に使う主要地域・学歴の対応を置く。`web/public/data/{country}/meta.json` が公開されている国だけが画面に出る。
- **国ごとの次元**: 年齢区分と学歴区分は `meta.json` の `ages` / `educations` で国ごとに持つ（英国は 18-21, 22-29, …、独仏伊は 18-29 / 30-49 / 50-69、学歴は ISCED の 3 区分、英国は学歴なし）。国をまたぐときは `mapEducation` で最も近い区分に置き換える。
- **職業の対応**: 国ごとに職業分類が違う（日本の職種、米国 SOC、英国 SOC 2020、カナダ NOC 2021、EU は ISCO-08 の大分類）。国際比較には、代表的な 30 職種について各国のコードを並べた共通職種表（`pipeline/career_pipeline/labels/common_occupations.json` → `web/public/data/occupations.json`。パイプラインで全コードの存在を検証）を使う。ISCO 大分類のように複数の職種にまたがるコードからは推測しない。表にない職種は、日米間のみ SOC 対応表で補い、それ以外は「職業」の条件を外して比較する。

| 国 | 分布の作り方 | method |
|---|---|---|
| 英国 | ASHE の公表分位点（p10〜p90）。非公表（CV 20% 超の 'x'）は、中央値の同じ側の公表分位点から (z, log 年収) で補間・外挿 | 0 / 4 |
| カナダ | 個票から直接（米国と同じ集計コード `microdata.py`）。通年（49〜52 週）・主にフルタイムの被用者 | 0 |
| 独・仏・伊 | 2022 年の平均 × 同じ集団の 2018 年（フルタイム）の D1・中央値・D9 の対平均比。p25・p75 は D1〜中央値、中央値〜D9 の間を対数で補間。2018 年に同じ集団がなければ 2022 年の職業群（OC1-5 / OC6-8 / OC7-9）、全体の順に使う | 3 |

**既知の限界**

- カナダの年収は 2020 年（コロナ禍の年）のまま。物価・賃金上昇の補正はしていない。職業は 26 区分しかない。
- 独仏伊の平均はフルタイム換算（パートを含む）、分布の形はフルタイムのみで、基準が少し違う。職業は 1 桁の大分類のみ、年齢は 3 区分、地域は平均のみ（男女・職業の内訳なし）。フランス・イタリアは従業員 10 人以上の企業のみ（ドイツも揃えて 10 人以上を使う）。
- 英国は学歴の軸がない。北アイルランドは職業別の内訳がない。4 桁職業×地域の表（表 15）は分位点が非公表のため使っていない。
- 生活費の地域差は日米のみ。ほかの国は「物価調整後」でも国内の地域差を補正しない（国際比較は購買力平価で補正）。
- 手取り:
  - ドイツは連邦財務省の公式源泉徴収アルゴリズム（PAP 2025）と一致する（年収 3万〜12万ユーロの4点で確認）。教会税は含まない。
  - フランスは非管理職を想定した社会保険料率で、補足年金の細かい区分・保険料は近似。
  - イタリアの地方付加税は全国平均の近似。
  - カナダの州税表で未確認の点: マニトバの税率区分（CRA と T4127 で値が違う）、ケベックの数値（Revenu Québec に直接アクセスできず、検索結果から取得）、ケベックの雇用所得控除の上限。

### 6.7 目標シミュレーション（Phase 4）

`web/src/engine/goal.ts`。目標は「A 歳で年収 X 以上」と「A 歳で管理職」の 2 種類。**すべて横断面の推定**で、今 A 歳の人の状態から求める。同じ人を追跡した到達率ではない。

- **到達率**:
  - 年収: 目標年齢のセル（ほかの条件はそのまま）で、`1 − パーセンタイル(X)` を求める。
  - 管理職: 各国の管理職の大分類の人数 ÷ 同じ条件の全体の人数。「管理職」は日本が管理的職業従事者、米国が SOC 11、英国が SOC 11・12、カナダが NOC 0、独仏伊が ISCO 1。人数には推計人口を使う。個票の国（米・加）は、セルに重み付き人口を追加した。
- **年齢別**: 同じ条件で年齢区分だけを動かした到達率。年齢の条件を外さないと求まらない区分は描かない。
- **条件を1つ変えると**: 職業（全大分類・全詳細職業）、学歴、地域、国（年収のみ。目標額は購買力平価で換算）を 1 つずつ変えて再計算し、上位 10 件を示す。次の選択肢は除外する。
  - 変えた条件が実際のセルに反映されない選択肢。
  - 基準（今の条件）より多くの条件を外してしまう選択肢。別の種類の集団と比べることになるため。
  - 管理職目標の国比較。管理職の定義が国ごとに大きく違い（例: 35〜39 歳女性で日本 1.3%、米国 21%）、比べても意味がないため。
- **到達している人の内訳**: 目標年齢で目標年収以上の人を 100% として、職業大分類と学歴の構成を「人数 × 到達率」で求める。学歴×年齢の表がない国（独仏伊）は全年齢で代用し、そう表示する。
- **扱わないもの**: 昇進率・転職率（パネルデータが必要。Phase 5）、起業・CTO（現在のデータは被用者のみ）。

### 6.8 転職・昇進・研究による効果（Phase 5）

**転職（日本）** `pipeline/career_pipeline/jp_mobility.py` → `web/public/data/jp/mobility.json`
- 雇用動向調査 令和7年 第13-2表: 転職入職者（入職前1年以内に雇用者として就業）の賃金変動区分の構成比（1割以上増／1割未満増／変わらない／1割未満減／1割以上減／不詳）× 性 × 年齢。
- 参考表2: 転職入職率（年間の転職入職者 ÷ 6月末の常用労働者）× 性 × 年齢。
- 転職した人の分布であって、転職しなかった人との比較（転職の効果）ではない。

**昇進（日本）**
- 賃金構造基本統計調査 令和7年 役職第1表・第2表: 部長級・課長級・係長級・職長級・非役職 × 性 × 学歴 × 年齢の労働者数と年収（所定内給与×12＋賞与。残業代を含まないので、本体の年収定義より少し低い）。
- 雇用期間の定めのない労働者、企業規模10人以上。
- 役職第1表の「役職計」には 4 区分に入らない役職も含まれるので、その差を「その他の役職」とし、分母は役職計＋非役職にする。
- 年齢別の構成は横断面で、昇進率ではない。

**転職（米国）** `pipeline/career_pipeline/us_cps_mobility.py` → `web/public/data/us/mobility.json`
- CPS ASEC 2024・2025 を合算（重みは 1/2）。
- 過去1年に2社以上で働いた人の割合（通年就業者）。
- 昨年の最長の仕事から職業大分類が変わった人の割合（現在就業中、職業が補完値でない人）。
- 勤め先1社／2社以上の人の年収中央値。
- 職業大分類 × 年齢（18-24, 25-34, …）× 性 × 学歴の各組み合わせで、標本 100 未満のセルは出さない。
- 2社以上＝転職ではない（季節労働などを含む）。年収は前年のもので、移った後の変化ではない。

**研究による効果** `pipeline/career_pipeline/labels/research_effects.json` → `web/public/data/research.json`
- 教育年数・大卒と高卒の差・大学院と大卒の差・語学・資格・転職・都市について、32 件。
- 各項目に出典 URL と、数値を含む原文の引用を付ける。数値は収集時にすべて出典で確認した。一部は公開時にも出典と照合した。
- 画面では「因果推定」（双子・制度改革・固定効果など）と「記述統計」（現状の差）を区別する。あなたの中央値に当てはめた金額を出すのは、因果推定の比例的な賃金効果だけにする。
- 他国のデータによる因果推定（例: スペインの大都市経験の効果）は、ラベルに対象国を書く。

### 6.9 自己申告データ（Phase 6）

- **構成**: 静的サイトのまま、保存先だけ Supabase（無料プランの PostgreSQL）を使う。
  - ブラウザは REST API に直接追加する。公開キーで許されるのは追加と削除関数だけ（行単位のアクセス制御）。
  - 集計は GitHub Actions が毎晩 service_role キーで行う。`web/public/data/community.json` をコミットし、それをきっかけにサイトを再デプロイする。
  - 個々の申告はサイトに一切出ない。
- **最小化**: 年齢は5歳階級、年収は丸め、日付のみ、自由記述なし。IP・時刻は保存しない（頻度制限用の時刻は別表に置き、1日で消す）。
- **公開の閾値**: 10件以上のグループのみ、四分位（丸め）と件数（5件単位に切り下げ）を出す。最小・最大値は出さない。
- **削除**: 送信時にブラウザで 160 ビットの削除用コードを作り、SHA-256 ハッシュだけを保存する。コードを入れると `delete_submission` 関数が該当行を消す。
- **検証**:
  - マイグレーションはローカルの PostgreSQL 16（pgserver）で確認した。
    - 公開ロールで読み取り・更新ができないこと。
    - 丸めていない額・範囲外の額・不正なハッシュを拒否すること。
    - 削除コードで消えること。
    - 21件目の連続送信を拒否すること。
  - 送信と削除の画面は、Supabase の REST API を模したサーバーで確認した。
- **課題**:
  - 申告者の偏り（代表的な標本ではない）。
  - いたずら。現状は頻度制限と値の範囲チェックのみ。必要なら CAPTCHA（Turnstile）を追加する。
  - 日ごとの差分から、珍しい組み合わせの存在が推測されるリスク（docs/PRIVACY.md）。
- 設定手順: [SUPABASE_SETUP.md](SUPABASE_SETUP.md)。プライバシー: [PRIVACY.md](PRIVACY.md)。

### 6.10 使いやすさ・詳細条件・安定性（Phase 7）

**使いやすさ**
- **リンクで共有**: 条件・金額の種類・タブ・言語を URL のフラグメント（`#c=JP&o=J012&…`）に入れる。フラグメントはサーバーに送られない。読み込み時は値を検証し、不正な値は捨てる（`web/src/urlState.ts`）。
- **タブ**: 「あなたの位置／目標／転職・昇進・学び／海外で働く／地図／みんなのデータ」。表示中のタブだけ描画するので、他国のデータなどは必要になったときに読み込む。目標タブは自国の結果を先に出し、他国のデータは届いてから追加する。
- **その他**: テーマ切り替え（自動／ライト／ダーク）、印刷・PDF（印刷用 CSS）。米国・英国の職業名（約 940）と米国の業界・専攻を日本語化した。

**詳細条件（ファセット）**
- 業界・企業規模・専攻・国籍・言語・働き方を、主な集計とは別のファイル `{country}/facets.json` に置く。
- キーは `<条件>=<値>|<職業>|<年齢>|<性別>`。組み合わせ爆発を避けるため、学歴・地域とは掛け合わせない。
- 国ごとの対応:

| 国 | 条件 |
|---|---|
| 日本 | 業界（産業大分類 16）、企業規模（10〜99／100〜999／1,000人以上 × 職種） |
| 米国 | 業界（18 部門）、専攻（10 分類）、国籍、英語力、働き方（雇用者／自営） |
| カナダ | 業界、専攻、国籍、公用語、働き方 |
| 独仏伊 | 業界（NACE）、企業規模 × 職業大分類（平均のみ。分布の形は 2018 年から） |

- 画面: 結果カードに「詳しい条件で見ると」、比較カードに条件ごとのタブを出す。
- 自営業者は主な集計（雇用者）に入れず、「働き方」の条件と「起業・自営」の目標にだけ使う。

**都市圏**
- 米国は大きい順に 30 都市圏。PUMA→CBSA の対応を公式ファイル（国勢調査区→PUMA、区の人口、郡→CBSA 2023）から作り、人口の半分以上がその都市圏にある PUMA を割り当てる。
- カナダは国勢調査個票の CMA（23 区分。一部は2都市圏をまとめた区分）。
- 都市圏は地域の選択肢に出る。タイル地図は州・県だけ。

**海外で働く**
- 7 か国の主な就労ビザ 17 経路（公式ページで確認、確認時点つき）。
- 給与基準がある経路は、行き先での同じ職業・年齢の中央値と比べて表示する。

**データの改善**
- カナダの 2020 年の所得を、平均週給の伸び（×1.188、表 14-10-0204）で 2025 年の水準に換算。
- 米国の転職データを CPS ASEC 2025〜2026 に更新。
- ドイツの手取りを連邦財務省の源泉徴収アルゴリズム（PAP 2025）に合わせた（4 点で一致を確認）。
- 通年フルタイムで年 1,000 未満の申告は誤記として除外。

**安定性**
- **公開データの検査** `pipeline/tests/test_published_data.py`:
  - 分位点の順序と正の値。
  - 平均が p10〜p90 から大きく外れないこと。
  - 全国中央値の妥当な範囲。
  - コードがメタデータにあること、地域ファイルがそろっていること。
  - ファセットの値がメタデータにあること。
  - 転職データの構成比、自己申告の公開閾値。
- **E2E テスト** `web/e2e/`（Playwright、デスクトップとスマホ）:
  - 初期表示、共有リンクの復元、年収入力とパーセンタイル。
  - 全 7 か国 × 全タブでエラーが出ないこと。
  - 国の切り替え、申告フォームの無効状態。
- **CI**: 公開データの検査・単体テスト・ビルド・E2E がすべて通ったときだけデプロイする。プルリクエストでも同じ検査を回す。
- **新しい公表の検知**: 毎月、各ソースの次の版の URL や e-Stat の年別件数を確認し、新しい版があれば Issue を立てる（`career_pipeline/releases.py`、`.github/workflows/releases.yml`）。データの更新そのものは、表の形式が変わることが多いので、検査つきの手作業にしている。

### 6.11 国際比較

- 為替レートと購買力平価（PPP）の両方で換算して並べて表示する。
- 職業の対応付けは、ISCO-08 の大分類を共通キーにする。加えて、代表的な約 30 職種は日本の職種と SOC の詳細コードの対応表を手作業で作る（例: ソフトウェア作成者 ↔ SOC 15-1252）。

## 8. UI（Phase 1）

1. **入力パネル**: 国、地域、年齢、性別（任意。「指定しない」を既定値にする）、学歴、職業、年収（任意）
2. **結果カード**:
   - 似た条件の人の年収分布（箱ひげ図 + 自分の位置）
   - 「あなたは上位 X%」（年収を入力した場合）
   - 使ったセルの条件と、フォールバックで外した条件
   - 出典・年次・サンプル数・推定方法
3. **比較**: 条件を 1 つ変えた集団（年齢 +5 歳、別の地域、学歴、別の国）の中央値を並べる
4. **注意書き**: 統計は集団の傾向であり個人の将来を予測しないこと、年収の定義が国ごとに違うこと

## 9. プライバシーと公平性

- 入力値を外部に送信しない。アナリティクスを入れる場合も、入力値は含めない。
- 性別・国籍は任意入力にし、未入力時は「計」のセルを使う。
- 属性による格差を表示するときは「現状の統計上の差」であって、その属性の人の能力や可能性を示すものではないと明記する。
